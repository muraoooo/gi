# お問合せフォーム機能 仕様書

## タスクID
001

## タスクタイトル
お問合せフォーム機能

## ユーザーニーズ

### 背景
ユーザーがWebサイトを通じて簡単に問い合わせを行えるようにする必要がある。

### ユーザーの要望
- 名前、メールアドレス、件名、本文を入力して問い合わせを送信したい
- 入力ミスを防ぐためにバリデーション機能が欲しい
- 送信完了の確認ができるようにしたい
- 管理者が問い合わせ内容を確認できるようにしたい

### 解決すべき課題
- 手軽に問い合わせができるUI/UX
- 入力データの正確性確保
- 管理者への通知機能
- 問い合わせ履歴の保存・管理

## 仕様要件

### 機能要件

#### 1. お問合せフォーム画面
- **URL**: `/contact`
- **入力項目**:
  - 名前（必須）
  - メールアドレス（必須、メール形式）
  - 件名（必須）
  - 本文（必須）
- **UIコンポーネント**: MUIのTextField, Buttonを使用

#### 2. 入力バリデーション
- **必須チェック**: すべての項目が必須
- **メール形式チェック**: メールアドレスが正しい形式か検証
- **エラー表示**: バリデーションエラー時は適切なエラーメッセージを表示

#### 3. メール送信機能
- **送信先**: 管理者メールアドレス
- **送信方法**: Nodemailerを使用
- **送信内容**: お問合せフォームの入力内容

#### 4. 送信完了画面
- **表示内容**: 送信完了メッセージ
- **表示タイミング**: メール送信成功後

#### 5. データ保存機能
- **データベース**: MongoDB
- **モデル**: Contact（Mongoose）
- **保存項目**:
  - name: 名前
  - email: メールアドレス
  - subject: 件名
  - message: 本文
  - createdAt: 作成日時（自動）

### 技術要件

#### フロントエンド
- **フレームワーク**: Next.js
- **UIライブラリ**: Material-UI (MUI)
- **使用コンポーネント**: TextField, Button
- **画面パス**: `/contact`

#### バックエンド
- **API Route**: `/api/contact`
- **HTTPメソッド**: POST
- **処理内容**:
  1. リクエストボディのバリデーション
  2. MongoDBへの保存
  3. Nodemailerによるメール送信
  4. レスポンス返却

#### データベース
- **DBMS**: MongoDB
- **ODM**: Mongoose
- **モデル名**: Contact
- **スキーマ**:
  ```javascript
  {
    name: String (required),
    email: String (required, email format),
    subject: String (required),
    message: String (required),
    createdAt: Date (default: Date.now)
  }
  ```

#### メール送信
- **ライブラリ**: Nodemailer
- **送信先**: 管理者メールアドレス（環境変数で設定）

## 処理手順設計

### 1. フロントエンド処理フロー

```
1. ユーザーが/contactページにアクセス
2. お問合せフォームが表示される
3. ユーザーが各項目を入力
4. 送信ボタンをクリック
5. クライアント側バリデーション実行
   - 必須チェック
   - メール形式チェック
6. バリデーションエラーがある場合
   - エラーメッセージを表示
   - 送信処理を中断
7. バリデーションOKの場合
   - /api/contactにPOSTリクエスト送信
8. レスポンス受信
   - 成功: 送信完了画面に遷移
   - 失敗: エラーメッセージを表示
```

### 2. バックエンド処理フロー

```
1. /api/contactエンドポイントでPOSTリクエスト受信
2. リクエストボディのバリデーション
   - name: 必須、文字列
   - email: 必須、メール形式
   - subject: 必須、文字列
   - message: 必須、文字列
3. バリデーションエラーがある場合
   - 400エラーを返却
4. バリデーションOKの場合
   - MongoDBにContactデータを保存
   - 保存成功後、Nodemailerでメール送信
5. メール送信成功
   - 200 OKレスポンスを返却
6. エラー発生時
   - 適切なエラーレスポンスを返却
```

### 3. データベース処理

```
1. MongooseでContactモデルを作成
2. 新しいContactインスタンスを作成
   - name, email, subject, messageを設定
   - createdAtは自動設定
3. save()メソッドで保存
4. 保存成功を確認
```

### 4. メール送信処理

```
1. Nodemailerの設定
   - SMTP設定（環境変数から取得）
   - 送信者情報
   - 受信者情報（管理者メールアドレス）
2. メール内容の作成
   - 件名: お問合せフォームからの問い合わせ
   - 本文: 入力された内容を整形して表示
3. sendMail()メソッドで送信
4. 送信成功を確認
```

## エラーハンドリング

### フロントエンド
- バリデーションエラー: 各フィールドにエラーメッセージを表示
- ネットワークエラー: 送信失敗メッセージを表示
- サーバーエラー: 適切なエラーメッセージを表示

### バックエンド
- バリデーションエラー: 400 Bad Request
- データベースエラー: 500 Internal Server Error
- メール送信エラー: 500 Internal Server Error（ただし、DB保存は成功している場合はログに記録）
