# Google認証機能 仕様書

## タスクID
002

## タスクタイトル
Google認証機能

## ユーザーニーズ

### 背景
ユーザーがWebサイトに安全かつ簡単にログインできるようにする必要がある。Googleアカウントを使用することで、パスワード管理の負担を軽減し、セキュリティを向上させる。

### ユーザーの要望
- Googleアカウントで簡単にログインしたい
- ログイン状態を維持したい（セッション管理）
- ログアウト機能が欲しい
- ログインしているユーザーのみアクセス可能なページ（ダッシュボード）が欲しい
- ヘッダーにログイン状態（アバター、名前）を表示したい

### 解決すべき課題
- 安全な認証システムの構築
- ユーザー情報の管理・保存
- 認証状態の管理（セッション）
- 認証が必要なページの保護
- ユーザーフレンドリーなUI/UX

## 仕様要件

### 機能要件

#### 1. Googleログインボタン
- **表示場所**: ヘッダー（未ログイン時）、ランディングページ、ログイン画面
- **UI**: MUIのButtonコンポーネントを使用
- **動作**: クリックでGoogle認証フローを開始

#### 2. ログイン画面
- **URL**: `/auth/signin`
- **表示内容**: Googleログインボタン
- **リダイレクト**: ログイン成功後、元のページまたはダッシュボードへ遷移

#### 3. ログアウト機能
- **表示場所**: ヘッダー（ログイン中）
- **動作**: クリックでセッションを破棄し、ログアウト

#### 4. セッション管理
- **ライブラリ**: NextAuth.js v5のセッション管理機能を使用
- **保存方法**: JWTまたはデータベースセッション（設定による）
- **有効期限**: NextAuth.jsのデフォルト設定に従う

#### 5. ユーザー情報の保存
- **データベース**: MongoDB
- **モデル**: User（Mongoose）
- **保存項目**:
  - name: ユーザー名（Googleから取得）
  - email: メールアドレス（Googleから取得、ユニーク）
  - image: プロフィール画像URL（Googleから取得）
  - role: ユーザー権限（デフォルト: 'user'）
  - createdAt: 作成日時（自動）
  - updatedAt: 更新日時（自動）

#### 6. 認証済みユーザーのみアクセス可能なダッシュボード
- **URL**: `/dashboard`
- **保護方法**: NextAuth.jsのミドルウェアで認証チェック
- **未認証時**: `/auth/signin`にリダイレクト
- **表示内容**: ユーザー情報、ウェルカムメッセージ

#### 7. ヘッダーにログイン状態表示
- **未ログイン時**: 「ログイン」ボタンを表示
- **ログイン中**: 
  - ユーザーアバター画像
  - ユーザー名
  - ログアウトボタン
- **表示場所**: 全ページのヘッダー（ランディングページを除く）

### 技術要件

#### 認証ライブラリ
- **NextAuth.js**: v5（最新版）
- **プロバイダー**: GoogleProvider
- **設定ファイル**: `auth.ts`（NextAuth.js v5の設定）

#### フロントエンド
- **フレームワーク**: Next.js
- **UIライブラリ**: Material-UI (MUI)
- **使用コンポーネント**: Button, Avatar, Menu, MenuItem
- **画面パス**: 
  - `/auth/signin`: ログイン画面
  - `/dashboard`: ダッシュボード

#### バックエンド
- **API Route**: NextAuth.jsが自動生成（`/api/auth/[...nextauth]`）
- **認証エンドポイント**: 
  - `/api/auth/signin`: ログイン
  - `/api/auth/signout`: ログアウト
  - `/api/auth/session`: セッション取得
  - `/api/auth/callback/google`: Google認証コールバック

#### データベース
- **DBMS**: MongoDB
- **ODM**: Mongoose
- **モデル名**: User
- **スキーマ**:
  ```javascript
  {
    name: String (required),
    email: String (required, unique, email format),
    image: String (optional),
    role: String (default: 'user', enum: ['user', 'admin']),
    createdAt: Date (default: Date.now),
    updatedAt: Date (default: Date.now)
  }
  ```

#### ミドルウェア
- **ファイル**: `middleware.ts`（Next.jsのミドルウェア）
- **保護対象**: `/dashboard`配下のすべてのページ
- **動作**: 未認証ユーザーを`/auth/signin`にリダイレクト

## 処理手順設計

### 1. Google認証フロー

```
1. ユーザーが「Googleでログイン」ボタンをクリック
2. NextAuth.jsがGoogle認証ページにリダイレクト
3. ユーザーがGoogleアカウントで認証
4. Googleが認証コードを返却
5. NextAuth.jsが認証コードをアクセストークンに交換
6. Google APIでユーザー情報を取得
   - name, email, image
7. コールバック関数でユーザー情報を処理
   - MongoDBにUserが存在するか確認
   - 存在しない場合は新規作成
   - 存在する場合は更新（必要に応じて）
8. セッションを作成
9. 元のページまたはダッシュボードにリダイレクト
```

### 2. ログイン処理フロー

```
1. ユーザーが/auth/signinページにアクセス
2. Googleログインボタンが表示される
3. ボタンクリックでGoogle認証フロー開始
4. 認証成功後、セッションが作成される
5. ダッシュボードまたは元のページにリダイレクト
```

### 3. ログアウト処理フロー

```
1. ユーザーがヘッダーの「ログアウト」ボタンをクリック
2. NextAuth.jsのsignOut()関数を呼び出し
3. セッションが破棄される
4. ホームページまたはログイン画面にリダイレクト
```

### 4. セッション管理フロー

```
1. ページアクセス時にNextAuth.jsがセッションを確認
2. セッションが有効な場合
   - ユーザー情報を取得
   - ヘッダーにユーザー情報を表示
3. セッションが無効または存在しない場合
   - 未ログイン状態として表示
   - 保護されたページにアクセスした場合はリダイレクト
```

### 5. ダッシュボード保護フロー

```
1. ユーザーが/dashboardにアクセス
2. ミドルウェアが認証状態をチェック
3. 認証済みの場合
   - ダッシュボードページを表示
4. 未認証の場合
   - /auth/signinにリダイレクト
   - 元のURLをcallbackUrlとして保存
```

### 6. ユーザー情報保存フロー

```
1. Google認証成功後、コールバック関数が実行
2. MongoDBでemailをキーにUserを検索
3. Userが存在しない場合
   - 新しいUserインスタンスを作成
   - name, email, imageを設定
   - roleはデフォルトで'user'
   - createdAt, updatedAtを設定
   - save()で保存
4. Userが存在する場合
   - name, imageを更新（必要に応じて）
   - updatedAtを更新
   - save()で保存
```

## 実装ファイル構成

```
プロジェクトルート/
├── auth.ts                    # NextAuth.js v5設定ファイル
├── middleware.ts              # 認証ミドルウェア
├── pages/
│   ├── auth/
│   │   └── signin.tsx         # ログイン画面
│   ├── dashboard/
│   │   └── index.tsx          # ダッシュボード
│   └── api/
│       └── auth/
│           └── [...nextauth].ts  # NextAuth.js API Route（v4の場合）
├── models/
│   └── User.ts                # Userモデル
├── components/
│   └── Header.tsx             # ヘッダーコンポーネント（ログイン状態表示）
└── .env.local                 # 環境変数（Google OAuth設定、MongoDB URI）
```

## 環境変数

```
# Google OAuth設定
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret

# NextAuth.js設定
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your-nextauth-secret-key

# MongoDB設定
MONGODB_URI=mongodb+srv://...
```

## Google OAuth設定手順

1. Google Cloud Consoleでプロジェクトを作成
2. OAuth同意画面を設定
3. 認証情報でOAuth 2.0 クライアントIDを作成
4. 承認済みのリダイレクトURIに以下を追加:
   - `http://localhost:3000/api/auth/callback/google`（開発環境）
   - `https://your-domain.com/api/auth/callback/google`（本番環境）
5. クライアントIDとクライアントシークレットを環境変数に設定
