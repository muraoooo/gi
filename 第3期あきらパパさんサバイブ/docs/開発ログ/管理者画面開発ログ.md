### Phase 2: DataGrid CSS インポートエラー

#### 発生したエラー
```
Server Error
SyntaxError: Unexpected token '.'

This error happened while generating the page. Any console logs will be displayed in the terminal window.

Call Stack
<unknown>
/Users/muraokadaichi/第3期あきらパパさんサバイブ/node_modules/@mui/x-data-grid/index.css (3)
```

#### エラー原因
- `@mui/x-data-grid` のCSSファイルがサーバーサイドレンダリング時にインポートされ、Node.jsがCSSを解析できなかった
- Next.jsのPages RouterではCSSモジュールの直接インポートがサーバーサイドでサポートされていない

#### 対処方法
1. `next.config.js` に `transpilePackages: ['@mui/x-data-grid']` を追加
2. CSSを `public/css/data-grid.css` にコピー
3. `pages/_app.tsx` でクライアントサイドのみでCSSを動的読み込み

```javascript
// pages/_app.tsx での対処
useEffect(() => {
  if (typeof window !== 'undefined') {
    const link = document.createElement('link');
    link.rel = 'stylesheet';
    link.href = '/css/data-grid.css';
    document.head.appendChild(link);
  }
}, []);
```

### Phase 3: generateUtilityClasses エラー

#### 発生したエラー
```
Server Error
TypeError: _mui_utils_generateUtilityClasses__WEBPACK_IMPORTED_MODULE_1__ is not a function

This error happened while generating the page.

Call Stack
generateUtilityClasses
node_modules/@mui/x-data-grid/esm/constants/gridClasses.js (6:28)
```

#### エラー原因
- `@mui/utils` の `generateUtilityClasses` 関数がwebpackによって正しく解決されていなかった
- ESMとCommonJSの混在による問題

#### 対処方法
`next.config.js` でwebpackエイリアスを修正:

```javascript
config.resolve.alias = {
  ...config.resolve.alias,
  '@mui/utils/generateUtilityClasses$': 
    require.resolve('@mui/utils/generateUtilityClasses/generateUtilityClasses.js'),
  '@mui/utils/generateUtilityClass$': 
    require.resolve('@mui/utils/generateUtilityClass/generateUtilityClass.js'),
};
```

また、`experimental.serverComponentsExternalPackages` から `@mui/x-data-grid` を削除（`transpilePackages` との競合を回避）

### Phase 5: fetchUsers 初期化エラー

#### 発生したエラー
```
Uncaught ReferenceError: Cannot access 'fetchUsers' before initialization
    at AdminUsers (users.tsx:80:36)
```

#### エラー原因
- `useCallback` で定義した `fetchUsers` 関数が `useEffect` より後に定義されていた
- JavaScript の Temporal Dead Zone (TDZ) により、関数が初期化される前に参照された

#### 問題のコード構造
```typescript
// ❌ 問題のあるコード順序
useEffect(() => {
  // ... 
  fetchUsers(); // ← fetchUsersはまだ定義されていない
}, [fetchUsers]);

const fetchUsers = useCallback(async () => { // ← ここで定義
  // ...
}, []);
```

#### 対処方法
関数定義の順序を変更:

```typescript
// ✅ 修正後のコード順序
const fetchUsers = useCallback(async () => { // ← 先に定義
  // ...
}, []);

useEffect(() => {
  // ... 
  fetchUsers(); // ← 定義済みの関数を参照
}, [fetchUsers]);
```

### Phase 6: 無限ローディング問題

#### 発生した問題
- コンソールに `Fetched users: Array(1)` と表示される（データ取得成功）
- しかし画面はローディングスピナーのまま止まる
- Fast Refresh が何度も実行される

#### 問題原因
1. `useEffect` の依存配列に `session?.user?.role` や `router` が含まれており、セッション状態が変わるたびに再実行
2. `fetchUsers` が呼ばれるたびに `setLoading(true)` が設定される
3. 結果として無限ループ的な状態に

#### 対処方法
**最終解決策: DataGridをMUI Tableに置き換え**

DataGridの複雑なSSR/CSR問題を回避するため、シンプルなMUI Tableコンポーネントに変更:

```typescript
// 変更前: DataGrid（問題多発）
import { DataGrid } from '@mui/x-data-grid';

// 変更後: MUI Table（安定動作）
import {
  Table,
  TableBody,
  TableCell,
  TableContainer,
  TableHead,
  TableRow,
} from '@mui/material';
```

また、`useRef` を使用して重複フェッチを防止:

```typescript
const hasFetched = useRef(false);

useEffect(() => {
  if (hasFetched.current) return; // 既にフェッチ済みなら何もしない
  
  if (status === 'authenticated' && session?.user?.role === 'admin') {
    hasFetched.current = true;
    fetchUsers();
  }
}, [status, session?.user?.role, router]);
```

## 技術的な学び

### 1. @mui/x-data-grid の問題点
- Next.js Pages Router との相性が悪い
- SSRでの動作に多くの設定が必要
- ESMモジュール解決で問題が発生しやすい

### 2. 推奨される代替案
- シンプルな一覧表示には MUI Table を使用
- 高度な機能（ソート、フィルター、ページネーション）が必要な場合は、カスタム実装か別ライブラリを検討

### 3. React Hooks の注意点
- `useCallback` で定義した関数は、`useEffect` より前に定義する
- 依存配列に含める関数は、必ず先に定義されている必要がある
- `useRef` を使用して不要な再実行を防止できる

### 4. Next.js 設定のベストプラクティス
- `transpilePackages` と `serverComponentsExternalPackages` は同じパッケージに設定しない
- ESMモジュールの問題は `esmExternals: false` で回避できることがある
- webpackエイリアスは `require.resolve` で正確なパスを指定
