## 1. エラーを見る3つの視点

### 視点①: エラーメッセージを「分解」して読む

エラーメッセージは必ず以下の要素に分解できます：

```
┌─────────────────────────────────────────────────────────────┐
│ エラーの種類        │ 何が起きたか（What）                   │
│ (TypeError, etc.)   │                                       │
├─────────────────────────────────────────────────────────────┤
│ エラーの場所        │ どこで起きたか（Where）                │
│ (ファイル名:行番号) │                                       │
├─────────────────────────────────────────────────────────────┤
│ コールスタック      │ どの流れで起きたか（How）              │
│ (at function...)    │                                       │
└─────────────────────────────────────────────────────────────┘
```

#### 例：今回のエラーを分解
```
TypeError: _mui_utils_generateUtilityClasses__WEBPACK_IMPORTED_MODULE_1__ is not a function
         ↑ 種類                              ↑ 何が起きた

at node_modules/@mui/x-data-grid/esm/constants/gridClasses.js (6:28)
                    ↑ どこで起きた（外部ライブラリ内）
```

**判断ポイント**: 
- 「自分のコード」で起きた → 自分で修正可能
- 「node_modules」で起きた → 設定やバージョンの問題

---

### 視点②: エラーの「タイミング」を見る

| タイミング | 意味 | よくある原因 |
|-----------|------|-------------|
| **ビルド時** | `npm run build` で発生 | 型エラー、インポートエラー、設定ミス |
| **サーバー起動時** | `npm run dev` 直後 | 環境変数不足、DB接続エラー |
| **ページ生成時** | 「This error happened while generating the page」 | SSR問題、モジュール解決エラー |
| **ブラウザ表示時** | ブラウザのコンソールに表示 | クライアントサイドのロジックエラー |

#### 今回の例
```
This error happened while generating the page.
              ↑
「ページ生成時」= サーバーサイドレンダリング（SSR）の問題
```

**判断ポイント**:
- SSRで起きる → サーバーとブラウザで動作が違うものを使っている可能性
- ブラウザのみで起きる → クライアント側のロジックを確認

---

### 視点③: エラーの「キーワード」から原因を推測

| キーワード | 推測される原因 |
|-----------|---------------|
| `is not a function` | 関数として呼び出せないものを呼んでいる、インポートエラー |
| `is not defined` | 変数や関数が定義されていない、スコープ問題 |
| `Cannot access before initialization` | 定義前に参照している（TDZ問題） |
| `WEBPACK` | モジュールバンドリングの問題 |
| `ERR_UNSUPPORTED_DIR_IMPORT` | ESM/CommonJSの互換性問題 |
| `Unexpected token` | 構文エラー、またはNode.jsが解釈できないファイル |

## 2. エラーの種類と判断基準

### 判断フローチャート

```
エラー発生
    │
    ▼
┌─────────────────────────────────────┐
│ Q1: エラーは自分のコード内か？      │
└─────────────────────────────────────┘
    │
    ├── Yes → 自分のコードを修正
    │
    └── No（node_modules内）
        │
        ▼
    ┌─────────────────────────────────────┐
    │ Q2: SSR/ビルド時のエラーか？        │
    └─────────────────────────────────────┘
        │
        ├── Yes → next.config.js の設定を確認
        │         - transpilePackages
        │         - serverComponentsExternalPackages
        │         - webpack alias
        │
        └── No（ブラウザ実行時）
            │
            ▼
        ┌─────────────────────────────────────┐
        │ Q3: 特定のライブラリが原因か？      │
        └─────────────────────────────────────┘
            │
            ├── Yes → 動的インポート（ssr: false）を検討
            │         または代替ライブラリを検討
            │
            └── No → ロジックエラーを確認
```

---

### エラー種類別の対処法

#### A. モジュール解決エラー
**特徴**: `Cannot find module`, `ERR_UNSUPPORTED_DIR_IMPORT`

```javascript
// 対処法1: 明示的な拡張子指定
import Icon from '@mui/icons-material/Edit.js'; // .js を追加

// 対処法2: next.config.js で transpile
transpilePackages: ['@mui/material', '@mui/icons-material'],

// 対処法3: webpack alias
config.resolve.alias = {
  '@mui/utils/formatMuiErrorMessage$': 
    require.resolve('@mui/utils/formatMuiErrorMessage/index.js'),
};
```

#### B. SSR関連エラー
**特徴**: 「generating the page」時に発生

```javascript
// 対処法: 動的インポートでSSR無効化
import dynamic from 'next/dynamic';

const ClientOnlyComponent = dynamic(
  () => import('problematic-library'),
  { ssr: false }
);
```

#### C. 初期化順序エラー
**特徴**: `Cannot access 'X' before initialization`

```javascript
// ❌ NG: 定義前に使用
useEffect(() => {
  fetchData(); // エラー！
}, [fetchData]);

const fetchData = useCallback(() => {}, []);

// ✅ OK: 先に定義
const fetchData = useCallback(() => {}, []);

useEffect(() => {
  fetchData(); // OK
}, [fetchData]);
```

#### D. 無限ループ・無限ローディング
**特徴**: 画面が止まる、同じログが繰り返し出る

```javascript
// ❌ NG: 依存配列に変化するものが多すぎる
useEffect(() => {
  setLoading(true);
  fetchData();
}, [session, router, fetchData]); // 全部変わる可能性

// ✅ OK: useRef でフラグ管理
const hasFetched = useRef(false);

useEffect(() => {
  if (hasFetched.current) return;
  if (status === 'authenticated') {
    hasFetched.current = true;
    fetchData();
  }
}, [status]);
```

## 3. 効果的なプロンプトの出し方

### 基本構造

```
【現象】何が起きているか
【エラー内容】エラーメッセージ全文
【期待する動作】本来どうなるべきか
【試したこと】すでに試した対処（あれば）
```

### 悪いプロンプト vs 良いプロンプト

#### ❌ 悪い例
```
エラーが出ます。直してください。
```
→ 情報が少なすぎて何もわからない

#### ❌ 悪い例
```
TypeError が出ました
```
→ エラーの詳細がないと原因特定できない

#### ✅ 良い例
```
管理者画面（/admin/users）でユーザー一覧が表示されません。

エラー内容:
TypeError: _mui_utils_generateUtilityClasses__WEBPACK_IMPORTED_MODULE_1__ is not a function
at node_modules/@mui/x-data-grid/esm/constants/gridClasses.js (6:28)

This error happened while generating the page.

DataGrid を使っていますが、SSRで問題が起きているようです。
解決方法を教えてください。
```

### 状況別プロンプトテンプレート

#### テンプレート1: ビルドエラー
```
npm run build でエラーが発生しました。

【エラーログ】
（ターミナルのエラーメッセージをコピペ）

【関連ファイル】
- ファイル名: xxx.tsx

このエラーを解決してください。
```

#### テンプレート2: 画面表示の問題
```
【現象】
（ページURL）にアクセスすると（症状）になります。

【ブラウザコンソールのエラー】
（コンソールのエラーメッセージをコピペ）

【期待する動作】
（本来どう表示されるべきか）

原因と解決方法を教えてください。
```

#### テンプレート3: 動作しない機能
```
【機能】
（何をしようとしているか）

【現象】
- ボタンをクリックしても反応しない
- ローディングが終わらない
- など

【コンソール出力】
（console.log の出力やエラーをコピペ）

どこに問題があるか特定して修正してください。
```

### プロンプトのコツ

1. **エラーメッセージは省略しない**
   - 「TypeError が出た」ではなく全文をコピペ

2. **スクリーンショットを活用**
   - 画面の状態がわかると判断が早い

3. **何を試したか伝える**
   - 「リロードしても同じ」「別のブラウザでも同じ」など

4. **ファイル名・行番号を含める**
   - エラーに含まれる情報をそのまま伝える

## 4. 実践例：今回のトラブルで学ぶ

### ケース1: CSSインポートエラー

#### 状況
```
SyntaxError: Unexpected token '.'
at @mui/x-data-grid/index.css (3)
```

#### 視点での分析
- **種類**: SyntaxError（構文エラー）
- **場所**: node_modules内のCSSファイル
- **タイミング**: ページ生成時（SSR）

#### 判断
「CSSファイルをNode.jsが解釈しようとしてエラー」
→ SSRでCSSを読み込まないようにする必要がある

#### 効果的なプロンプト
```
SSRでCSSファイルが読み込まれてエラーになっています。

SyntaxError: Unexpected token '.'
at @mui/x-data-grid/index.css

CSSをクライアントサイドでのみ読み込む方法を教えてください。
```

---

### ケース2: 関数が関数じゃないエラー

#### 状況
```
TypeError: xxx is not a function
at @mui/x-data-grid/esm/...
```

#### 視点での分析
- **種類**: TypeError
- **キーワード**: `is not a function` + `WEBPACK`
- **場所**: ESMモジュール内

#### 判断
「Webpackがモジュールを正しく解決できていない」
→ インポートパスやモジュール解決設定の問題

#### 効果的なプロンプト
```
MUI DataGridを使用時にTypeErrorが発生します。

TypeError: _mui_utils_generateUtilityClasses__WEBPACK_IMPORTED_MODULE_1__ is not a function

Webpackのモジュール解決に問題がありそうです。
next.config.js の設定で解決できますか？
```

---

### ケース3: 無限ローディング

#### 状況
- コンソールに「Fetched data」と出る（データ取得成功）
- でも画面はローディングのまま
- 同じログが何度も出る

#### 視点での分析
- **現象**: データは取れているのに表示されない
- **手がかり**: 同じログが繰り返される

#### 判断
「useEffect が何度も実行されて、loading状態がリセットされている」
→ 依存配列の問題、または状態管理の問題

#### 効果的なプロンプト
```
【現象】
- コンソールに「Fetched users: Array(1)」と表示される
- しかし画面はローディングスピナーのまま
- 同じログが複数回出力される

【推測】
useEffect が繰り返し実行されているようです。

無限ループを防ぐ方法を教えてください。
```

## 5. 予防策：同じトラブルを起こさないために

### チェックリスト：新しいライブラリを使う前に

```
□ Next.js（Pages Router）との互換性を確認したか
□ SSRで動作するか確認したか
□ 公式ドキュメントでNext.js用の設定を確認したか
□ 似たような問題のGitHub Issueがないか検索したか
```

### チェックリスト：useEffect を書くとき

```
□ 依存配列に含めるものは本当に必要か
□ 関数は useEffect より前に定義しているか
□ 無限ループの可能性はないか
□ クリーンアップは必要か
```

### チェックリスト：エラーが出たとき

```
□ エラーメッセージを最後まで読んだか
□ エラーの発生タイミングを確認したか
□ 自分のコードか外部ライブラリか確認したか
□ 同じエラーをGoogle/GitHub で検索したか
```

### 代替案を知っておく

| 問題のあるライブラリ | 代替案 |
|---------------------|--------|
| @mui/x-data-grid（SSR問題多い） | MUI Table（シンプルで安定） |
| 複雑なSSR対応ライブラリ | 動的インポート（ssr: false） |

## まとめ：トラブル対応の心構え

### 1. 焦らずエラーを「読む」
- エラーメッセージには原因のヒントがある
- 英語でも翻訳して理解する

### 2. 「どこで」「いつ」起きたかを特定
- サーバー側か、ブラウザ側か
- ビルド時か、実行時か

### 3. 小さく試す
- 一度に大きな変更をしない
- 一つ変更したら確認する

### 4. 代替案を持つ
- 一つの方法に固執しない
- 「別の方法でもいい」という柔軟性

### 5. 記録を残す
- 何をしたか、どう解決したかをメモ
- 次に同じ問題が起きたときの参考に
